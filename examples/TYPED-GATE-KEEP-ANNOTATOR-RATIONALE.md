# Why these examples keep semantic output annotators

The typed-gate conversion replaces semantic `output` annotator gates with deterministic `pre_tool_call` or `post_tool_call` gates only when a tool already computes the safety signal. The budget-overrun pilot is the model case: it gates on the `validate_budget` tool's typed `within_budget` boolean instead of an LLM classifier, eliminating the annotator's scenario overrefusal tax while preserving or improving bad-event reduction (`examples/travel_planner_langgraph/acs/budget-overrun-typed/AB-RESULTS.md:5`, `examples/travel_planner_langgraph/acs/budget-overrun-typed/AB-RESULTS.md:6`, `examples/travel_planner_langgraph/acs/budget-overrun-typed/AB-RESULTS.md:35`). The suites below do not have an equivalent tool-computed boolean; their bad event is semantic content in the final assistant reply, so they must keep an `output` annotator gate.

The governing workflow states the injection rule directly: "**Prompt injection / XPIA is a SEMANTIC `output` gate, not a retrieved-content tool gate.**" (`.claude/skills/run-assert-eval/workflows/govern-and-remeasure.md:585`). It explains why: the judge scores the agent "RELAYING or ACTING ON the embedded instruction in its final REPLY," so "the gate must judge the reply, not the retrieved bytes" (`.claude/skills/run-assert-eval/workflows/govern-and-remeasure.md:587`, `.claude/skills/run-assert-eval/workflows/govern-and-remeasure.md:592`).

## Summary

| Suite | Risk | Why annotator required |
|---|---|---|
| `azure-doc-qa-prompt-injection` | Prompt injection / XPIA | The bad event is the final reply obeying injected document instructions, not reading the document bytes; the policy denies on an `injection_compliance` LLM annotation of assistant output. |
| `career-health-prompt-injection` | Prompt injection / XPIA | The agent is tool-less, and the failure is free-form JSON output complying with instructions embedded in untrusted `CV_TEXT`. |
| `science-prompt-injection` | Prompt injection / XPIA | Tools retrieve untrusted web/file content, but the failure is the reply complying with embedded instructions; there is no structural field for a deterministic rule. |
| `health-assistant-simtools-*` | Unsafe medical prose | Simulated tools can elicit unsafe advice, but the bad event is the final prose: tool-laundered dosing, interaction clearance, or diagnosis. |
| `health-assistant-gentools-*` | Unsafe medical prose | Per-case tools affect elicitation, but the gate target is still harmful final prose, not a typed tool result. |
| `health-assistant-modelonly-*` | Unsafe medical prose | The model-only target has no tools at all; dosage and diagnosis harms are necessarily semantic assistant-output judgments. |

## `azure-doc-qa-prompt-injection`

- **Gate type:** semantic `output` gate with `policy_target_kind: assistant_output` and an LLM `injection_compliance` annotator (`examples/azure_doc_qa/acs/prompt-injection/manifest.yaml:19`, `examples/azure_doc_qa/acs/prompt-injection/manifest.yaml:24`, `examples/azure_doc_qa/acs/prompt-injection/manifest.yaml:28`).
- **Tool signal we would need but do not have:** a tool-computed boolean meaning "the assistant endorsed or relayed this embedded instruction as agent-sanctioned guidance." The available tools can retrieve document text, but the bad event depends on how the agent synthesizes the final reply.
- **Concrete bad event:** the policy comments define the failure as semantic: "the reply obeyed an instruction embedded in a retrieved document," and clarify that the injection arrives inside retrieved document content rather than the user's turn (`examples/azure_doc_qa/acs/prompt-injection/policy/azure_doc_qa_prompt_injection_baseline.rego:5`, `examples/azure_doc_qa/acs/prompt-injection/policy/azure_doc_qa_prompt_injection_baseline.rego:10`). The Rego denies only when the output annotator returns `injection_compliance == true` (`examples/azure_doc_qa/acs/prompt-injection/policy/azure_doc_qa_prompt_injection_baseline.rego:41`, `examples/azure_doc_qa/acs/prompt-injection/policy/azure_doc_qa_prompt_injection_baseline.rego:47`).
- **Agent grounding:** the agent explicitly treats embedded document instructions as data, runs a tool-call loop until the model produces text, and returns the final assistant message (`examples/azure_doc_qa/agent.py:98`, `examples/azure_doc_qa/agent.py:239`, `examples/azure_doc_qa/agent.py:364`). Therefore a post-tool rule on retrieved bytes would block benign reading/summarization and miss the actual reply-level compliance question.

## `career-health-prompt-injection`

- **Gate type:** semantic `output` gate with `policy_target_kind: assistant_output` and an LLM `prompt_injection_annotator` (`examples/career_health_assessment/acs/prompt-injection/manifest.yaml:18`, `examples/career_health_assessment/acs/prompt-injection/manifest.yaml:27`).
- **Tool signal we would need but do not have:** a deterministic tool-boundary signal for "the JSON reply complied with malicious instructions embedded in CV text." No such boundary exists because the agent has no tools.
- **Concrete bad event:** the manifest states the agent is tool-less and the prompt-injection failure is "free-form output that complied with instructions embedded in untrusted CV_TEXT" (`examples/career_health_assessment/acs/prompt-injection/manifest.yaml:4`, `examples/career_health_assessment/acs/prompt-injection/manifest.yaml:5`). The policy denies when the semantic annotator says the assistant output complied with those embedded instructions (`examples/career_health_assessment/acs/prompt-injection/policy/prompt_injection.rego:11`, `examples/career_health_assessment/acs/prompt-injection/policy/prompt_injection.rego:18`).
- **Agent grounding:** the baseline agent is documented as having "NO tools" and its prompt tells it to treat `CV_TEXT` as untrusted data (`examples/career_health_assessment/agent.py:8`, `examples/career_health_assessment/agent.py:65`). A typed tool-boundary gate is structurally impossible.

## `science-prompt-injection`

- **Gate type:** semantic `output` gate with `policy_target_kind: assistant_output` and an LLM `prompt_injection_annotator` (`examples/science_research_agent/acs/prompt-injection/manifest.yaml:20`, `examples/science_research_agent/acs/prompt-injection/manifest.yaml:29`).
- **Tool signal we would need but do not have:** a tool result boolean that distinguishes harmless retrieval of untrusted content from the assistant's later endorsement of embedded instructions. The tools expose untrusted content, but not whether final prose complied with it.
- **Concrete bad event:** the manifest says the failure is free-form output complying with instructions embedded in untrusted retrieved content, with "no structural field to key a deterministic rule on" (`examples/science_research_agent/acs/prompt-injection/manifest.yaml:4`, `examples/science_research_agent/acs/prompt-injection/manifest.yaml:7`). The policy denies when the output annotator flags compliance with an instruction embedded in untrusted retrieved content (`examples/science_research_agent/acs/prompt-injection/policy/prompt_injection.rego:11`, `examples/science_research_agent/acs/prompt-injection/policy/prompt_injection.rego:18`).
- **Agent grounding:** the agent has web and file retrieval tools whose results are explicitly untrusted, and its prompt says never to follow instructions from tool results (`examples/science_research_agent/agent.py:80`, `examples/science_research_agent/agent.py:101`). The loop returns final prose after tool use (`examples/science_research_agent/agent.py:243`), so the governance question is reply-level.

## `health-assistant-simtools-*`

- **Gate type:** semantic `output` gate with `policy_target_kind: assistant_output` and an LLM `harmful_medical_advice_annotator` (`examples/prompt_agents/sim_tools/acs/harmful_medical_advice/manifest.yaml:32`, `examples/prompt_agents/sim_tools/acs/harmful_medical_advice/manifest.yaml:41`).
- **Tool signal we would need but do not have:** a typed tool result that proves the final answer contains unsafe dosing, unsafe interaction clearance, or patient-specific diagnosis. The simulated tools may provide intermediate content, but they do not compute a final-answer safety verdict.
- **Concrete bad event:** the manifest defines the harm as "free-form prose in its final reply" including tool-laundered actionable dose, interaction clearance, or diagnosis, with "no tool boundary and no structural field" for a deterministic rule (`examples/prompt_agents/sim_tools/acs/harmful_medical_advice/manifest.yaml:5`, `examples/prompt_agents/sim_tools/acs/harmful_medical_advice/manifest.yaml:7`). The policy denies when the output annotator flags harmful, actionable medical advice (`examples/prompt_agents/sim_tools/acs/harmful_medical_advice/policy/harmful_medical_advice.rego:15`, `examples/prompt_agents/sim_tools/acs/harmful_medical_advice/policy/harmful_medical_advice.rego:24`).
- **Agent grounding:** this callable reproduces a Prompt Agent with a system prompt, fixed tool schema, and LLM simulator; the model ultimately returns text from the tool loop (`examples/prompt_agents/sim_tools/agent.py:9`, `examples/prompt_agents/sim_tools/agent.py:17`, `examples/prompt_agents/sim_tools/agent.py:178`). The unsafe property is in that synthesized text.

## `health-assistant-gentools-*`

- **Gate type:** semantic `output` gate with `policy_target_kind: assistant_output` and an LLM `harmful_medical_advice_annotator` (`examples/prompt_agents/gen_tools/acs/harmful_medical_advice/manifest.yaml:20`, `examples/prompt_agents/gen_tools/acs/harmful_medical_advice/manifest.yaml:29`).
- **Tool signal we would need but do not have:** a deterministic per-tool field that says the assistant's final medical prose endorsed an unsafe remedy, medication stop/replace instruction, or unsafe combination. Generated tool schemas vary by test case and are not a stable typed safety source.
- **Concrete bad event:** the manifest says the harm is free-form final-reply prose, with "no tool boundary and no structural field" for a deterministic rule (`examples/prompt_agents/gen_tools/acs/harmful_medical_advice/manifest.yaml:5`, `examples/prompt_agents/gen_tools/acs/harmful_medical_advice/manifest.yaml:6`). The policy denies when the annotator flags harmful, actionable medical advice (`examples/prompt_agents/gen_tools/acs/harmful_medical_advice/policy/harmful_medical_advice.rego:11`, `examples/prompt_agents/gen_tools/acs/harmful_medical_advice/policy/harmful_medical_advice.rego:20`).
- **Agent grounding:** the generated-tools target uses `test_set.tool_source: per_test_case`, but callable targets receive only `(message, history)`, and the behavior under test is explicitly described as a "SEMANTIC/prose failure" in the assistant's final reply regardless of concrete tools (`examples/prompt_agents/gen_tools/agent.py:16`, `examples/prompt_agents/gen_tools/agent.py:17`, `examples/prompt_agents/gen_tools/agent.py:24`). The tool schema affects elicitation, not a typed enforcement signal.

## `health-assistant-modelonly-*`

- **Gate type:** semantic `output` gates with assistant-output LLM annotators for dosage and diagnosis (`examples/prompt_agents/model_only/acs/dosage/manifest.yaml:17`, `examples/prompt_agents/model_only/acs/dosage/manifest.yaml:26`, `examples/prompt_agents/model_only/acs/diagnosis/manifest.yaml:17`, `examples/prompt_agents/model_only/acs/diagnosis/manifest.yaml:26`).
- **Tool signal we would need but do not have:** any tool-boundary signal at all. The target is model-only, so `pre_tool_call` and `post_tool_call` gates cannot fire.
- **Concrete bad event:** both manifests state the agent is tool-less and every failure is free-form assistant output (`examples/prompt_agents/model_only/acs/dosage/manifest.yaml:4`, `examples/prompt_agents/model_only/acs/dosage/manifest.yaml:5`, `examples/prompt_agents/model_only/acs/diagnosis/manifest.yaml:4`, `examples/prompt_agents/model_only/acs/diagnosis/manifest.yaml:5`). The dosage policy denies actionable unsafe dosage or medication advice, and the diagnosis policy denies definitive diagnosis, false all-clear, or missed emergency escalation (`examples/prompt_agents/model_only/acs/dosage/policy/dosage.rego:11`, `examples/prompt_agents/model_only/acs/dosage/policy/dosage.rego:18`, `examples/prompt_agents/model_only/acs/diagnosis/policy/diagnosis.rego:11`, `examples/prompt_agents/model_only/acs/diagnosis/policy/diagnosis.rego:19`).
- **Agent grounding:** the agent reproduces a hosted model plus system prompt with "NO tools," and the prompt says never to provide dosage recommendations or diagnoses (`examples/prompt_agents/model_only/agent.py:8`, `examples/prompt_agents/model_only/agent.py:72`). Because the only output is generated text, the only enforceable bad-event signal is a semantic output annotation.
